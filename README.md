# Dota 2 Deterministic Review Workbench

玩家 `173776719` 的个人 Dota 2 天梯复盘工作台。线上地址：[dota.custard.top](https://dota.custard.top)。

产品行为是刻意按需的：

- 首页只读取缓存并显示最近 10 局；只有点击“刷新比赛”才启动 OpenDota 同步任务。
- 进入单局时只读取比赛事实和已有复盘状态；只有点击“生成数据复盘”才启动证据抓取和公式计算。
- 点击分析后由按需工作流获取 STRATZ + OpenDota 完整证据，包括分钟经济/经验/补刀、购买、死亡、击杀助攻、位置、目标、视野、十人数据和同英雄百分位。
- 必需字段存在缺口时，后端只继续请求解析或证据任务，不发布、不缓存建议，也不使用估算值补齐。
- 所有结论、排序和下一局行动均由版本化确定性公式生成。项目没有大模型调用、模型绑定、Prompt 或概率式文本生成路径。

## Architecture

```text
Browser
  |-- GET /api/matches ----------------------> Cloudflare Worker -> KV cache
  |-- POST /api/matches/refresh -------------> Worker -> fixed GitHub Actions workflow
  |                                              -> OpenDota latest 10 + full details -> KV
  |-- GET /api/matches/:id ------------------> Worker -> prewarmed KV detail
  `-- POST /api/reviews/:id -----------------> Worker
          |-- no current evidence -----------> fixed GitHub Actions workflow
          |                                     -> STRATZ + OpenDota -> versioned KV evidence
          |-- complete evidence in KV -------> deterministic analyzer -> formula score/ranking
          `-- required field missing --------> parse/evidence retry; no review is published
```

Cloudflare Pages serves `public/`. The Python Worker serves `dota.custard.top/api/*`. GitHub Actions performs both OpenDota cache refreshes and STRATZ evidence fetches because the upstream services rate-limit or block Cloudflare Worker egress. The browser never receives a service token.

The repository also retains historical static reports as an archive. They are not regenerated by page load, automatic timers, or the primary review flow.

## API Contract

| Method | Path | Behavior |
| --- | --- | --- |
| `GET` | `/api/health` | Runtime health check |
| `GET` | `/api/matches` | Read the cached latest-10 list only |
| `POST` | `/api/matches/refresh` | Manually dispatch the fixed latest-10 sync job; returns `202` while processing |
| `GET` | `/api/matches/:id` | Load factual detail for a match in the current latest 10 |
| `GET` | `/api/reviews/:id/status` | Read existing review status; never starts analysis |
| `POST` | `/api/reviews/:id` | Return cached review or start evidence acquisition and analysis |

Refresh requests have a server-side cooldown and processing-state deduplication. The browser polls cache status with `GET`; it never starts a second job automatically. Review polling deduplicates STRATZ and OpenDota requests and publishes only after the role-aware field ledger has no blocking gaps. Refresh and evidence jobs are restricted to the configured repository, workflows, branch, fixed player account, and current latest-10 match IDs.

## Local Development

Python 3.13, Node.js, and `uv` are required.

```powershell
python -m uv sync --locked --python 3.13 --group cli
python scripts/build_workbench_site.py
python scripts/build_worker_bundle.py
powershell -ExecutionPolicy Bypass -File scripts/run_worker_dev.ps1
```

In another terminal, serve the Pages output through the local API proxy:

```powershell
python scripts/run_workbench_dev.py --port 8808 --api-origin http://127.0.0.1:8791
```

Open `http://127.0.0.1:8808`. Local runtime secrets belong in ignored `.dev.vars`; do not put credentials in source files or command output.

## Deployment

Pushes to `main` run `.github/workflows/deploy-pages.yml`. The workflow tests the full project, builds and deploys the Worker, then deploys `public/` to Cloudflare Pages project `cstd-help`.

`.github/workflows/on-demand-match-refresh.yml` has only `workflow_dispatch`; it writes the latest 10 matches and all 10 factual details to KV. `.github/workflows/on-demand-review.yml` is also dispatch-only and writes complete STRATZ/OpenDota evidence for one selected recent match. `.github/workflows/refresh-reports.yml` is a manual-only legacy archive maintenance workflow and has no schedule.

GitHub Actions secrets:

- `CLOUDFLARE_ACCOUNT_ID`
- `CLOUDFLARE_API_TOKEN` with access to the Worker, Pages project, and dedicated review KV namespace
- `STRATZ_API_KEY`, used only by the on-demand evidence workflow

Cloudflare Worker encrypted secret:

- `GITHUB_DISPATCH_TOKEN`, authorized to dispatch `on-demand-match-refresh.yml` and `on-demand-review.yml` in `Muguett-DBY/cstd-help`

The Worker uses the dedicated `CSTD_HELP_REVIEW_CACHE` KV namespace. Never commit `.dev.vars`, `.env*`, access tokens, API keys, generated runtime bundles, or local browser artifacts.
