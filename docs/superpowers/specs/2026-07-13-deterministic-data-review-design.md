# Pure Data Dota Review Design

## Goal

The product reviews only player `173776719`. It lists the latest ten ranked matches from cached OpenDota data, refreshes that list only on explicit user action, and fetches full STRATZ/OpenDota evidence only when the user opens a match and requests a review.

No runtime path may call a language model, model gateway, prompt endpoint, or probabilistic ranking service. Every conclusion and action must be produced by deterministic formulas from named source fields.

## Data Contract

Each review records a field ledger with source, required/applicable state, observed fields, missing fields, coverage percentage, and status. Required fields depend on match facts and role: death coordinates are required only when deaths occurred; vision events are required for position 4/5 and informational for cores; zero-event arrays are valid available data when the source returned the field.

The evidence package includes core stats, all ten participants, role/position, ability build, final items, minute LH/gold/XP/damage arrays, purchases, deaths, coordinates, kills/assists, objectives, vision, benchmarks, performance context, and extended combat/economy/activity metrics. A review is publishable only when its required ledger has no blocking gaps.

## Formula Contract

The deterministic engine publishes scorecards for laning, economy, survival, map conversion, and role execution when their inputs exist. Every scorecard exposes its formula identifier, human-readable equation, input values and sources, score, threshold, and interpretation. Missing inputs remove that component from the weighted total; they are never estimated.

Findings receive a deterministic issue score from priority, measured magnitude, evidence coverage, and role relevance. Stable sorting plus dimension diversity selects at most four actions. Action text, training goal, and success metric remain those generated by evidence rules; formulas only rank verified findings.

## Runtime And Cache

The Worker constructs only cache, OpenDota, analyzer, and GitHub workflow adapters. Review responses use `analysis_mode: deterministic_formula`, expose a formula version, and store under a bumped review schema so prior model-ranked cache entries cannot be reused.

The UI calls the feature “数据公式复盘”, displays the scorecards and field ledger, and contains no model-related states or copy. Offline HTML generation uses the same deterministic review object.

## Verification

Unit tests cover formulas, missing-input behavior, role-aware field requirements, cache invalidation, and absence of model bindings. Integration tests build Worker/Pages assets. Acceptance fetches the real latest ten matches, generates a full review for at least one current match, inspects rendered desktop/mobile pages, verifies GitHub Actions, and checks the production domain.
